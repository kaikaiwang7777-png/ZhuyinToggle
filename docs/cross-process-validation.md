# 跨程序焦點實驗紀錄

## 條件與觀察

- 兩個分離程序：自建 WinForms TestHost 與背景 FocusController。控制器透過 UI Automation 尋找宿主的輸入欄位和按鈕，沒有透過自訂 IPC 要宿主執行焦點操作。宿主只公開觀察狀態。
- 專用可丟棄文字框中，以實際注音鍵位提交「電腦中國」作為繁體基準；宿主的 Microsoft Bopomofo 設定檔與可觀察的組字狀態檢查通過，記錄 IME 開始／結束／結果各 2 次。這不是所有 TSF 狀態均已結束的完整證明。
- 一次 `--focus` 嘗試：宿主記錄輸入框失焦，接著按鈕取得焦點，事件時間相差約 3 ms；失焦時文字長度 4、選取起點 4、選取長度 0。測試前後畫面可見宿主，不能據此證明全程前景未變。
- 控制器在嘗試返回文字框前，顯示「無法確認目標焦點，停止不搶回」，因此沒有完成焦點往返。此判定是前景、最近輸入及 UIA 焦點的複合條件，現有紀錄無法判定是哪一項造成；不能宣稱原因已確定。停止後可見測試文字未變，但未完成返回焦點，因此返回後的選取與游標狀態未測得。
- 程式控制流程在呼叫按鈕 SetFocus 前會寫入並回讀目標 REG_SZ；此次沒有獨立紀錄保存該次寫入的中間讀回結果，僅可作為程式流程推論，不能當成獨立驗證。備份為 `REG_SZ 0x00000000`；關閉兩個實驗程序後，另行查詢確認目前值亦為 `REG_SZ 0x00000000`。

## 結論與限制

跨程序焦點移到按鈕：**PASS，1 次觀察**。跨程序焦點完整返回：**FAIL，1 次嘗試中安全條件未確認而停止**。繁簡輸出往返、不中斷輸入、恢復後游標／選取及三次有效往返：**NOT TESTED**。不重置焦點的本輪對照、記事本及 Chrome：**NOT TESTED**。

這個候選方案必須實際改變輸入焦點，目前未證明可安全恢復；不能由此推論所有公開 API 都不可能實現跨程序更新。依停止條件不再擴大同類實驗，不應進入第三方程式測試或正式產品整合。正式程式維持未知狀態，PR 保持 Draft，不發布。

## 後續診斷修正（尚待互動實測）

控制器現將按鈕 SetFocus 後同步檢查與 BeginInvoke 檢查分開記錄，逐項列出前景、GetLastInputInfo 與 UIA 焦點結果，並記錄 UIA 元素識別資料、焦點變更事件、REG_SZ 回讀及單調時鐘。宿主的焦點事件也使用單調時鐘。只記錄測試宿主程序的 UIA 焦點事件，紀錄保留本機；不移除原本安全檢查。尚未進行新的實機切換，之前的合併錯誤仍無法分辨成因，沒有證據可認定為 UIA 狀態延遲或安全檢查誤判。未加入等待，必須先取得實測時序才能評估。

## 後續互動實測

在使用者實際輸入「電腦中國」、宿主觀察 IME 開始／結束／結果各一次後，一次跨程序嘗試的 REG_SZ 由 `0x00000000` 寫為 `0x00000001` 並回讀相符。按鈕 SetFocus 之後的同步檢查與 BeginInvoke 檢查，前景、最近輸入、焦點六項均 PASS；最近輸入差值 0 ms。

單調時鐘頻率 10,000,000 ticks/s。依事件時間：文字框 Leave 為 0 ms；按鈕 Enter 為 +3.498 ms；按鈕 UIA FocusChanged 為 +32.485 ms。按鈕 Leave 為 +53.161 ms；文字框 Enter 為 +55.921 ms；控制器報「未能恢復焦點」為 +83.758 ms；文字框 UIA FocusChanged 為 +90.009 ms。宿主記錄輸入框取得焦點時原文字長度 4、選取 4,0；內容仍為基準字串。但返回時控制器的失敗條件仍合併「前景不符或焦點不符」，沒有分別記錄其當時值，不能證明究竟哪一項失敗，也不能斷言 UIA 觀察延遲是唯一原因。使用者之後嘗試再次輸入，但可觀察的文字及組字次數沒有變化，故切換後實際輸出標為 NOT TESTED，不把該輪算成有效繁簡往返。

備份值為 `REG_SZ 0x00000000`；正常關閉控制器後回讀已還原，兩個測試程序均結束。原始診斷日誌僅留本機。正式產品未修改；未進入記事本或 Chrome 測試。

## 返回焦點判定修正後的實測

控制器針對返回後前景、最近輸入與 UIA 焦點逐項判定；只有前景與輸入均安全且焦點尚未一致，才等待 UIA 焦點事件（上限 250 ms），期間持續核對狀態及程序身分，並在成功後重檢。本輪一次操作中，按鈕 SetFocus 後及返回前的六項檢查均 PASS；REG_SZ 繁→簡寫入並回讀一致。input.SetFocus 返回後立即檢查：前景 **FAIL**（取得的 HWND 與原宿主 HWND 不同，且數值與 UIA 回報的輸入欄位 HWND 相同）、最近輸入 **PASS**（差值 0 ms）、焦點 **FAIL**（查詢仍是按鈕）。控制器依規定立即停止，沒有進入事件等待；這次資料不能證明前景 HWND 變化的原因，也不能證明單純的 UIA 延遲。

宿主事件顯示欄位 Leave → 按鈕 Enter → 按鈕 Leave → 欄位 Enter；欄位 Enter 時文字長度 4、選取 4,0，未觀察到全選。後續使用者再次輸入後可見「電腦中國電腦中國」，沒有產生預期的簡體後綴；後一次組字的計數未被獨立保存，不能把這輪計為完整、有效的輸出往返。未進行下一次切換或第三方程式驗證。正常退出後設定回讀為原本 `REG_SZ 0x00000000`，兩個實驗程序均結束。
