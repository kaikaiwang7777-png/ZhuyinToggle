# 跨程序焦點實驗紀錄

## 條件與觀察

- 兩個分離程序：自建 WinForms TestHost 與背景 FocusController。控制器透過 UI Automation 尋找宿主的輸入欄位和按鈕，沒有透過自訂 IPC 要宿主執行焦點操作。宿主只公開觀察狀態。
- 專用可丟棄文字框中，以實際注音鍵位提交「電腦中國」作為繁體基準；宿主的 Microsoft Bopomofo 設定檔與可觀察的組字狀態檢查通過，記錄 IME 開始／結束／結果各 2 次。這不是所有 TSF 狀態均已結束的完整證明。
- 一次 `--focus` 嘗試：宿主記錄輸入框失焦，接著按鈕取得焦點，事件時間相差約 3 ms；失焦時文字長度 4、選取起點 4、選取長度 0。測試前後畫面可見宿主，不能據此證明全程前景未變。
- 控制器在嘗試返回文字框前，顯示「無法確認目標焦點，停止不搶回」，因此沒有完成焦點往返。此判定是前景、最近輸入及 UIA 焦點的複合條件，現有紀錄無法判定是哪一項造成；不能宣稱原因已確定。停止後可見測試文字未變，但未完成返回焦點，因此返回後的選取與游標狀態未測得。
- 程式控制流程在呼叫按鈕 SetFocus 前會寫入並回讀目標 REG_SZ；此次沒有獨立紀錄保存該次寫入的中間讀回結果，僅可作為程式流程推論，不能當成獨立驗證。備份為 `REG_SZ 0x00000000`；關閉兩個實驗程序後，另行查詢確認目前值亦為 `REG_SZ 0x00000000`。

## 結論與限制

跨程序焦點移到按鈕：**PASS，1 次觀察**。跨程序焦點完整返回：**FAIL，1 次嘗試中安全條件未確認而停止**。繁簡輸出往返、不中斷輸入、恢復後游標／選取及三次有效往返：**NOT TESTED**。不重置焦點的本輪對照、記事本及 Chrome：**NOT TESTED**。

這個候選方案必須實際改變輸入焦點，目前未證明可安全恢復；不能由此推論所有公開 API 都不可能實現跨程序更新。依停止條件不再擴大同類實驗，不應進入第三方程式測試或正式產品整合。正式程式維持未知狀態，PR 保持 Draft，不發布。
