# ZhuyinToggle 開發交接

## 專案狀態與 Owner 決策

核心目標「微軟注音實際繁簡輸出可靠切換」尚未達成，**沒有可供日常使用的版本**。Owner 不批准 Preview、正式 v0.1.0 或合併 main。保留公開倉庫、既有功能分支與 Draft PR #1；停止重複跨程序焦點實驗，不再擴大測試工具。原始碼、歷史測試紀錄與實驗程式保留供接手者追溯；原始私人診斷紀錄不公開。

## 已驗證的受限功能

以受限開發版互動桌面測試：預設 Win+Alt+C 十次 REG_SZ 設定往返與回讀正確；自訂快捷鍵跨重啟保留及觸發、衝突時保留舊鍵、系統匣左鍵與雙擊、正常退出後釋放快捷鍵、重複啟動保護均已觀察通過。程序 token 非提升。自啟動 Run 值開關有讀回證據，但**真實重新登入尚未驗證**；完整資源釋放、真實登錄存取失敗及帳號群組身分尚未全面驗證。[完整驗收](restricted-acceptance.md)。

## 未解決的核心阻斷

- `Enable Simplified Chinese Output` 的 REG_SZ 可寫入並回讀，但**設定值、實際輸出與系統匣顯示是不同事物**。目前沒有可靠的實際模式查詢；灰色「?」維持未知，不能顯示虛假的繁／简狀態。
- 記事本與 Chrome 本輪在寫入簡體設定後，立即與依指示正常離開／返回後仍觀察到繁體輸出。由於未建立實際簡體輸出，簡→繁切換未驗證。輸入法身分依使用者操作；本輪未獨立以 TSF 驗證，焦點事件也未獨立記錄，不能擴大推論。[具體測試表](restricted-acceptance.md)。
- Windows 原生微軟注音設定頁曾在受控測試中使既有記事本輸出更新；僅憑登錄寫入或 ProcMon 擷取不能推論其完整內部 API、通知、IPC 或記憶體行為。[既有研究](ime-validation.md)、[焦點驗證](cross-process-validation.md)。

## 若 Owner 未來重新啟動開發

1. 先閱讀以上紀錄及 PR 歷史，固定 Windows 版本、同一使用者與互動工作階段，確認 Microsoft Bopomofo 身分，並以原生設定頁建立實際組字控制組。
2. **優先研究原生設定頁在寫入 REG_SZ 之外，是否有必要的設定通知或其他操作**；只使用有文件支持或可重現的證據。ProcMon 沒看到事件並不等於其他機制不存在。
3. 候選機制須能安全、可重複地驗證實際注音輸出，分別在記事本及 Chrome 確認繁→簡→繁；設定回讀、輸出成功及圖示同步需分開記錄。不得重啟 Explorer／輸入法、強制變更其他程式焦點、注入程序或以文字轉換冒充切換。
4. 不要再次從零研究或反覆測試已停止的跨程序焦點路線；沒有新證據前不把焦點實驗整合進產品。通過核心實機驗收並由 Owner 決定前，不轉正式、合併或發布。

本輪檢查未發現 ZhuyinToggle 或專案測試程序仍在執行；原先的繁體 `REG_SZ 0x00000000`、停用的自啟動及原預設快捷鍵設定均已確認。預設快捷鍵可暫時註冊，檢查後已立即釋放。這些是檢查當下的狀態，不代表之後使用者不能自行變更。
